# SOLID Principles

SOLID is a set of five principles for writing clean, scalable, maintainable object-oriented code. Each letter stands for one principle.

## The Five Principles

| Letter | Principle | Status |
|---|---|---|
| S | [Single Responsibility Principle (SRP)](01-single-responsibility-principle/README.md) | Covered |
| O | [Open/Closed Principle (OCP)](02-open-close-principle/README.md) | Covered |
| L | [Liskov Substitution Principle (LSP)](03-liskov-substitution-principle/README.md) | Covered |
| I | [Interface Segregation Principle (ISP)](04-interface-seggregation-principle/README.md) | Covered |
| D | Dependency Inversion Principle (DIP) | Not covered yet |

## Index

- [S — Single Responsibility Principle (SRP)](01-single-responsibility-principle/README.md): A class should have only one reason to change.
- [O — Open/Closed Principle (OCP)](02-open-close-principle/README.md): Software entities should be open for extension, but closed for modification.
- [L — Liskov Substitution Principle (LSP)](03-liskov-substitution-principle/README.md): Subtypes must be substitutable for their base types without breaking the program.
- [I — Interface Segregation Principle (ISP)](04-interface-seggregation-principle/README.md): Don't force a class to depend on methods it does not use.
- D — Dependency Inversion Principle (DIP): High-level modules should not depend on low-level modules; both should depend on abstractions. _(Coming soon)_
